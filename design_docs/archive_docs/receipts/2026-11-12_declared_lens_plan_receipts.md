## 2026-11-13: L3, the hot-path probe

Branch `lens/l3` (Mere, on `706fdca1a`); not landed. The probe is `crates/graph/graph-kernel/examples/lens_dispatch.rs` (package `mere-kernel`, features `query,fixtures`). It adds two dev-dependencies to `mere-kernel` (`eidetic` with `pack-signing,pack-authoring`, and `identity`), the same rows the engine's own tests carry, because the probe loads the core pack and the workspace stand-in through the real loader (D13) and the stand-in is authored TOML. No crate enters the graph that was not already in it. No enum is removed.

- What each path reads per edge. Enum path: a `RelationKind` column, matched per edge through `built_in_relation_stratum` (called across the crate boundary, as the kernel calls it at admission, migration and placement) and `RelationKind::family`. Those are the only two enum reads per edge the engine makes; the seven other observed axes (durability, retractability, projectability, force, symmetry, presentation, derivation) have no enum path today. Pack path: the edge's relation interned once, outside the timed loop (at load or projection), to a dense `u32` id (an open predicate takes one extra slot after the last term, holding the core defaults); per frame, one indexed read of the axis row. Variants: `pack_loaded` reads the loader's own `TermTable` entries (`terms.get(id).row.stratum`); `pack_flat` reads a compact table of the observed axes copied once at load; `pack_flat_call` is the same read behind `#[inline(never)]`, the bound if the lookup crosses a crate boundary; `pack_flat_all_axes` reads all eight observed axes and the family. Family is a string on the loader's term entry, so its dense form is part of the flat table's precomputation.
- Controls. Positive: the enum path, in the same run and over the same column; each group's checksums are asserted equal across paths. Negative: a loop doing only a `black_box` read of each element of each column (the kinds column and the ids column), not subtracted anywhere. Equality: `check_equal` compares enum and pack stratum and family for all 46 kinds (44 sub-kinds, Traversal, an open predicate) through the loaded table and the flat table at startup; the unit test `enum_and_pack_agree_for_every_relation_kind` asserts the same.
- Mutation (instrument proof). `LENS_MUTATE=1` flips the stratum of one flat row (`Semantic(Hyperlink)`). The startup check caught it ("Semantic(Hyperlink): enum (0,0) pack Flat { stratum: 1 ... } loaded Resource"), and with the startup check passed over, the timed loop's checksum assertion failed (`mixed pack_flat_stratum: checksum differs from the enum path`, left 3018, right 2820 at 10k). `a_wrong_pack_row_fails_the_equality_check_and_the_checksum` asserts both in a test.
- Columns. The P5 chain graph (every edge one open predicate) is the denominator's graph and would be a branch-predictor-trivial column, so the relation column is a deterministic xorshift draw over all 46 kinds ("mixed"), with a column of one kind ("uniform", `Semantic(Cites)`) as the friendly control. The column has one entry per edge (N). The graph's own edges are not the column; this is a stated difference from "the same graph".
- Run: Windows 11 laptop, release, `CARGO_PROFILE_DEV_DEBUG=0`, five runs of `lens_dispatch 10000 100000`, each figure the median of five run medians (301 sweeps per run at 10k, 101 at 100k; variants interleaved in each rep). CPU load before each run (percent; no cargo or rustc process running): 13, 21, 23, 29, 84. Logs: `C:/t/lens-l3-logs/run1.log` to `run5.log`, `load.log` and `agg.py`, kept outside the repo. A first attempt overlapped two copies of the script and was discarded.
- Headless frame share, same runs (P5's steady and after-edit rows): 10k, point 0.0107 ms, two-hop 4.40 ms, after one edit point 112.9 ms, two-hop 117.6 ms; 100k, point 0.0103 ms, two-hop 45.0 ms (46 ms on the quiet ThinkPad), after one edit point 1,245 ms, two-hop 1,285 ms.

Reading: the pack path is at or below the enum path in every configuration but one, and the one is 0.10% of the steady two-hop frame, inside P5's 1.5% noise band and far inside D9's 5%. The enum path is slower on a mixed column because its match mispredicts (5.2 ns per edge against 0.4 ns for a table read); on a uniform column it predicts (0.7 ns) and the pack path ties it, or loses by one call. The percentage against the steady point frame is not a verdict: that frame reads no edge's kind, the sweep is an upper bound the frame does not run, and a 0.01 ms denominator makes any per-edge sweep large. D9 does not say which frame its 5% is of; that comes back as a fork in the lane's report. Noise: the enum uniform row at 10k is bimodal across runs (a code-layout effect), the loaded-table rows spread 7 to 9%, and run 5 started at 84% CPU load; no conclusion rests on a gap under 0.1% of a frame.
