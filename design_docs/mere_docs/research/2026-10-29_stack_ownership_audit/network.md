## Priority findings

1. **Replace commodity text encodings.** Truchman's Base32/Base64 is straightforward duplicated standards machinery, with a mature configurable library alternative.
2. **Evaluate replacing the feed semantic parser.** Errand already delegates XML tokenization to quick-xml, but still owns feed namespaces, content forms, link selection, extensions, and a naive HTML stripper. feed-rs overlaps strongly, including the separate JSON Feed path, but the adapter must retain podcast resources and diagnostics.
3. **Evaluate shared low-level MessagePack and protobuf engines.** Pure Rust and no_std are not sufficient reasons to own these mechanics: rmp supports both, and generic protobuf wire readers exist without importing third-party radio schemas.
4. **Evaluate upstream p2panda-spaces before growing custom group/key orchestration.** It is already present in the pinned supplier. The custom community constitution, capability semantics, and authority folds remain local responsibilities.
5. **Keep the purchased transport engines.** iroh/quinn, snow, str0m, Hyper/rustls/h3/tungstenite already own most expensive networking standards. Swapping wrappers for a different comprehensive stack would be architectural churn without demonstrated reduction.
6. **Treat independent radio stacks as explicit expensive product commitments.** Embedded Rust supports the decision, but does not make routing, interoperability, flow control, cryptographic composition, resource transfer, and version drift cheap.

## Ranked inventory

### Replace

**Truchman Base32/Base64. High confidence; small change, broad reuse.**

Murm `crates/truchman/src/encoding.rs:1-60` implements padded I2P Base64 with the `-~` alphabet, optionally padded decoding, trailing-bit validation, and lowercase unpadded Base32. The entire file is 123 lines including tests. Use `data-encoding` with an explicit alphabet, padding, and trailing-bit specification; its [Specification API](https://docs.rs/data-encoding/latest/data_encoding/struct.Specification.html) directly supports those choices. Keep destination certificate parsing, caller input policy, and private-key custody outside the codec.

Deciding test: every current vector plus empty input, all one/two-byte tails, malformed/extra padding, impossible lengths, nonzero trailing bits, alphabet confusion, and destination round-trip. Current decoder intentionally accepts padded or unpadded input; a strict padded default is not behavior-equivalent. Recommendation means replace after this small compatibility gate, not that this gate has run.

### Evaluate with a strong presumption toward reduction

**Errand feed walker and summary stripping. High confidence in overlap; medium confidence in full replacement.**

Errand `crates/errand/src/parse/feed.rs:104` wraps quick-xml with a custom event walker. Its own module documentation at lines 16-23 says summary HTML is stripped, Atom XHTML child content is not captured, and JSON Feed is left to consumers. `strip_html_tags:167` is a boolean `<`/`>` scan, not an HTML parser: it does not recognize quoted delimiters, raw-text elements, entities, or block boundaries. `inspect_element:228` recognizes literal prefixes such as `itunes:image`, `podcast:chapters`, and `podcast:transcript`, so namespace aliases are not treated by URI identity.

[feed-rs](https://docs.rs/feed-rs/latest/feed_rs/) provides a unified Atom/RSS/JSON Feed parser, already built on quick-xml. Its [entry model](https://docs.rs/feed-rs/latest/feed_rs/model/struct.Entry.html) carries content, summary, dates, links, language, and MediaRSS. Replacing quick-xml alone accomplishes nothing: it is already purchased. The useful cut is the semantic walker and duplicated JSON mapping. Keep a small adapter to product facts, raw podcast chapter/transcript URLs, unknown-extension diagnostics, and explicit degradation reporting. Feed-rs synthesizes an ID when absent; distinguish that from source-supplied identity. Its larger model and dependency graph are costs to measure, not pure-Rust blockers.

Deciding test: all existing podcast fixtures plus aliased namespace prefixes, default namespaces, Atom `type=text/html/xhtml`, mixed child markup, quoted `>` in HTML attributes, script/style content, entities, adjacent blocks, malformed XML, JSON attachments, missing IDs, relative resources and xml:base, original date strings, unsupported extension diagnostics, and bounded input/output. Do not silently sanitize or normalize retained content. If generic feed-rs cannot retain podcast extensions and diagnostics, use it for standards content plus a narrow extension pass, or keep the existing walker until a smaller parser proves the contract. HTML summary extraction should use an existing HTML tokenizer or library; feed-rs does not itself establish the desired plain-text extraction policy.

**MessagePack primitives and bounded subset decoders. High overlap, medium fit confidence.**

Murm has a 538-line `crates/retinue/src/msgpack.rs` for signed artifact envelopes, a 239-line `crates/outrider/src/portable/msgpack.rs` for LXMF payload fields, and host-side `rmpv` adapters in `outrider/src/propagation/msgpack.rs` (143 lines) and other codecs. Retinue documents canonical shortest-form output and a depth ceiling of 16. Portable LXMF owns a complete marker skipper with a separate nesting bound of 16. These are meaningful hostile-input safeguards, but not novel wire mechanics.

[rmp](https://docs.rs/rmp/latest/rmp/) explicitly supports no_std, low-level markers/primitives, zero-copy decoding, and compact encoders. Prefer evaluating its primitive layer under the existing shape/depth/length policy rather than swapping in an unconstrained `Value` allocation tree. rmpv is already used for hosted flows. An adapter can preserve the subset's refusals instead of widening accepted types simply because the library supports them.

Deciding test: byte-identical artifact signatures/oracle vectors, negative and unsigned integer boundaries, str/bin distinction, extension skip correctness, floats only where LXMF permits them, truncation at every offset, overlarge lengths/counts before allocation, nested containers at/above the ceiling, trailing bytes, and no_std firmware code-size/allocation receipt. If an adapter retains nearly all parser code, replacement value is smaller; consolidation of common primitives may still win.

**Sennet generic protobuf reader/writer. Medium confidence, a better candidate than replacing the radio implementation.**

`crates/sennet/src/protobuf.rs` is a 302-line independently written schema-free wire reader. It yields field-number/value pairs, implements varints, fixed32/fixed64 and length-delimited fields, and writes tags/varints. The radio policy interprets fields separately. `PROVENANCE.md` excludes third-party Meshtastic firmware, schemas, and generated bindings; it does not require owning Google's generic wire format.

[quick-protobuf BytesReader](https://docs.rs/quick-protobuf/latest/quick_protobuf/reader/struct.BytesReader.html) offers direct tag/scalar/bytes/unknown-field operations. [Buffa](https://docs.rs/buffa/latest/buffa/) offers a pure Rust no_std runtime, low-level wire codec, borrowed views and configurable decoding limits, though it is a larger/newer candidate. [Prost](https://docs.rs/prost/latest/prost/) supports no_std, but its `encoding` module is documented as internal, so do not build the public abstraction around that unsupported API. None of these trials needs an upstream radio schema: field policy can remain independently authored.

Deciding test: stock observations retain identical numbered fields and opaque values; truncated, overflow and overlong varints, invalid tag numbers/wire types, enormous lengths, groups, duplicate fields, trailing garbage, complete versus partial parse, borrowed byte lifetime, no_std size. If a library forces generated schemas or loses exact structural observations, retain the scanner. Generic protobuf adoption should be a distinct decision from relaxing the project's protocol-source boundary.

**Remaining KISS duplication. Medium confidence, small consolidation.**

`crates/selvage/src/kiss.rs` already centralizes allocation-free escaping, byte scanning and fixed-buffer framing for firmware and Tulle; `crates/tulle/src/kiss.rs:1-9` is explicitly a Vec storage adapter over it. Do not count this as two independent implementations. However, `crates/retinue/src/iface/kiss.rs:37` has a separate escape encoder and private deframer at line 76. Evaluate reusing Selvage's scanner while preserving command-byte policy and KISS-TNC flow/beacon state. This is internal reuse rather than a reason to add a new external framing crate.

Deciding test: command byte treatment, malformed escape reset, oversize resynchronization, empty data frames, split chunks, READY timeout and station-ID cadence. Retinue's encoder treats the command separately from the payload, so a mechanical whole-frame substitution may alter behavior.

### Evaluate strategically, without assuming a drop-in replacement

**Gemot group/key integration versus p2panda-spaces. Medium-high confidence in substantial overlap, low-medium confidence in a complete cut.**

Gemot `crates/gemot/src/moot/group.rs:23-34` already uses p2panda-auth `GroupCrdt`, `StrongRemove`, and p2panda-encryption IDs. It adds membership wrappers, verified apply, auth heads, and bound group/scope key epochs. Commons' `encrypted.rs`, `keys.rs`, `chat.rs` and parking/pruning adapters tie these to Stickleback and durable retained records. This is not a custom cryptographic primitive implementation, but it is custom orchestration around primitive libraries.

The pinned p2panda supplier already includes `p2panda-spaces`. Its [Manager API](https://github.com/p2panda/p2panda/blob/main/p2panda-spaces/README.md) combines auth groups with data encryption and supports nested groups, dynamic actors, private space identifiers and shared groups across encryption boundaries. It explicitly requires causally ordered, signed, verified messages and remains unstable. Evaluate it as the owner of generic group transitions and key agreement; retain project-specific constitution and authority interpretation.

Deciding test: concurrent add/remove and nested device membership, departure key rotations, forward versus durable-data profile behavior, offline revoked peer catch-up, withheld or pruned epochs, replay and cold reopen, Muniment storage without SQLite, Personae derived writers, export/drop behavior, and namespace separation across lanes. Existing `COMMONS_CHAT_PROFILE` deliberately uses durable-data encryption; switching to a forward-secure profile changes product behavior and cannot be treated as incidental library adoption.

**Generic causal processing, lifecycle and pruning versus high-level p2panda. Medium overlap confidence, lower replacement confidence.**

Pinned supplier `p2panda/README.md` advertises causal ordering, topic sync, stream acknowledgements/replay, pruning, persistence, and transactional processing. Murm's `gossip_sync.rs` already delegates catch-up to Stickleback's JoinedSpace/LogSync; Commons also uses the shared causal projection seam, rather than independent replication engines everywhere. Do not count domain projections as a duplicate transport or CRDT implementation.

The high-level p2panda crate may reduce repeated actor lifecycle and generic processing code in Stickleback/hosts, but its documented persistent store is SQLite and its APIs remain unstable. Muniment backend choice, browser storage, retained-operation admission, explicit authority checkpoints, and carrier-neutral integration are real constraints. Evaluate narrow extraction/adoption of processing and replay facilities before replacing the stack wholesale. Deciding test is convergence under operation reorder/duplication, missing parents, revoked writers, authorized pruning, crash/reopen and independently named lanes on the same endpoint, across native/browser backends.

**p2panda fork retirement/upstreaming. High confidence that the fork is substantive and currently necessary; replacement status unqualified.**

Murm native lock pins `mere-p2panda-net` 0.7.5 at `1f69c9bc`. Compared with its upstream parent `c99f5014`, local delta covers 32 files, 1380 insertions/125 deletions, including tests and docs. Concrete added seams include pluggable address-book storage; observed inbound address hints with capacity/TTL; atomic gossip event subscription plus existing-neighbour snapshot; explicit per-instance LogSync ALPN; lifecycle/actor cleanup; compatible dependency versions. This is not a version-only fork.

Aim to upstream generic extension seams or retire them when equivalent released APIs exist, instead of treating the fork as permanent product differentiation. A current upstream merge or release comparison is required before claiming any patch obsolete. Deciding test: two independent LogSync lanes sharing one endpoint; late subscriber sees existing neighbours without a gap; no actor leaks after shutdown; address-book persistence/closure through Muniment; bounded address hints and partition recovery; dependency identity and dalek compatibility. Returning to upstream without those seams would reintroduce documented failure classes.

**SAM/I2P client. Medium confidence to retain now, low confidence a replacement saves complexity.**

Truchman owns bounded reply framing, quote/escape parsing, validated command serialization, destinations/certificates, retained data after handshake, and STREAM lifecycle. It does not implement the I2P router. `lib.rs:13` explicitly says datagram sessions are absent. [I2P's SAM documentation](https://www.i2p.net/en/docs/api/samv3/) lists i2p-rs as a Rust STREAM/DGRAM/RAW client, and [i2p-rs](https://github.com/i2p/i2p-rs) calls itself early development with an unstable API. This is a legitimate comparison candidate, not established evidence of a superior drop-in engine.

Deciding test: SAM 3.2 quoted replies, injection refusal, partial line bounds, destination certificate lengths/signature types, retained post-header bytes, persistent destination reuse, concurrent connects/accepts, cancellation and reconnect, supported router matrix. Replacing the small client with a full router such as a Rust I2P implementation would increase scope. Buy the encodings first; evaluate the SAM shell only if its maintenance grows.

### Keep delegated engines and thin application seams

**Iroh/QUIC transport. High confidence.** `native/crates/transport/Cargo.toml` declares compatible requirements for iroh (`1.0.3`), iroh-blobs (`0.103`), and iroh-tickets (`1.0`); these are manifest requirements rather than a claim about the exact lockfile-resolved patch releases. `p2panda_transport.rs:7-20` says p2panda-net is endpoint authority and replaced a hand-rolled IrohTransport router. Keep application ALPN routing, bounded accept, owner-selected discovery/relay policy, Personae seed release and shutdown custody. Tokio semaphore/channel composition in `bounded_accept.rs` is ordinary admission policy, not a custom QUIC replacement. libp2p would be a large parallel framework with no demonstrated benefit to these seams.

**Noise session. Keep the existing snow engine; reassess incremental value per carrier.** The protocol implementation is already bought through snow 0.10. Owned code is stream framing plus Ed25519 identity binding to the Noise handshake. `noise.rs:24-29` misleadingly implies iroh relays can read the underlying traffic. Official [iroh documentation](https://docs.rs/iroh/latest/iroh/) says relays only forward end-to-end encrypted traffic. Persona identity separation, carrier-independent session identity, or untrusted application relays can justify an additional layer; ordinary iroh relay confidentiality alone cannot. Deciding test: an explicit threat model and persona/carrier key separation, transcript binding, wrong-key/reflection/replay refusals, frame/cancel/EOF behavior, and measured overhead on slow radio. This is a reason to correct rationale and avoid redundant activation, not a finding that all Noise should be removed.

**WebRTC. High confidence to keep current purchase.** `native/crates/webrtc-carrier/Cargo.toml` selects str0m 0.23.1 with `rust-crypto`, and the browser adapter uses web-sys RTC APIs. SDP/ICE/DTLS/SCTP are not independently implemented. Core owns bounded frames, invitation IDs, role-tagged fingerprints and challenge-derived links; native driver owns socket/runtime pumping and browser owns event backpressure. The manifest records a prior str0m/webrtc-rs comparison, but that historical size result was not rerun here. Deciding test for future changes: cross-browser native interoperability, reordered/chunked frames, backpressure cancellation, ICE restart/forced relay, invitation replay and fingerprint mismatch; shared-core Wasm qualification remains separate from native runtime evidence.

**HTTP/TLS/WebSocket. High confidence to keep the shared wire layer.** `wire/crates/wire/Cargo.toml` already uses Hyper/hyper-util, hyper-rustls/rustls, Quinn+h3+h3-quinn, and tokio-tungstenite. `lib.rs:1-4` keeps Fetch/CORS/cookies/redirect/decoding above the raw one-hop engine. Generic reqwest might shorten some connection code, but a default client can quietly add policy, redirect, decoding or proxy choices. The existing narrow seam is justified for a browser. Retained `testing/receipts/wire-engines/README.md` describes the supplier extraction and focused software qualification; it is a historical source-bound receipt, not a new test run.

**DNS integration deserves an evaluate/fix entry, not a claim of a handwritten DNS stack.** `wire/src/h3_client.rs:39` uses blocking `ToSocketAddrs` within async code, selects the first address, binds an IPv4 endpoint, creates a fresh QUIC endpoint per fetch and fully collects the body. No DNS parser is implemented there. Evaluate host-injected asynchronous resolution using the existing resolver/connector or Hickory only if its actual policy is needed. Deciding test: IPv6-only origin, multiple addresses with first-address failure, cancellation/deadline, resolver consistency with browser policy, no blocking executor, response-size limits and streaming. Merely adding another resolver can worsen privacy and duplicate DNS caches.

**Small-web protocols and TLS. Retain protocol adapters, consolidate common mechanics if profitable.** Errand owns DICT/Finger/FSP/Gemini/Gopher/Guppy/Kepler/Misfin/Nex/Scorpion/Scroll/Spartan/text protocol grammars, limits and client/server shells. URL/IDNA/percent encoding and TLS/X.509/crypto are already delegated to url/idna/percent-encoding, rustls/tokio-rustls, rcgen, x509-parser and ring/SHA crates. Gemini `tofu.rs`/`tls.rs` is a host-selectable trust/pin policy around rustls, not a home-grown TLS stack. Replacing it with WebPKI-only HTTPS trust would change the protocol. Shared bounded-line/deadline/cancellation helpers could reduce repeated code, but there is no verified mature single library covering this full protocol set with the same host custody. Deciding tests are the existing per-protocol limit/deadline suites plus cancellation, malformed replies, injection, TOFU changed-pin refusal, port-scoped identities and native/browser feature cones.

### Strategic expensive ownership

**Retinue RNS plus Outrider LXMF.** Retinue owns routing/path expiry, announcements and freshness, bounded queues, IFAC, link establishment/proof/liveness, channel windows, resource segmentation/retry/compression, ratchets, interfaces and NomadNet. Outrider adds direct/opportunistic/propagation delivery, stamps/tickets, fields, stores and snapshots. These are substantial independent protocol implementations, not small adapters. Native Python RNS/LXMF sidecar mode could lower compatibility maintenance for desktop-only configurations, but cannot replace no_std firmware and introduces an IPC/custody/runtime boundary. Other Rust stacks should be compared on the full required surface, not language match alone. `token.rs:3-34` explains why a standard Fernet crate is not equivalent to RNS's stripped token form; CBC/HMAC/HKDF are already library primitives. `testing/receipts/rns-1.5.7-repin/README.md` records historical pinned RNS/LXMF live interop and version-specific boundaries. Keep running black-box oracle differential coverage as versions move; this review provides no new runtime qualification.

**Sennet Meshtastic interoperability and Tucket MeshCore.** Both are no_std radio implementations on shared Tulle. Sennet is deliberately independently observed and schema-free; Tucket `cipher.rs:22` is an attributed MIT MeshCore port, so their provenance strategies differ. Sennet already buys AES-CTR/CCM and X25519; Tucket buys AES/dalek/HMAC/SHA/subtle. Tucket's AES-ECB plus two-byte HMAC is the compatibility wire construction, not a generic secure-message format to export elsewhere. A stock companion/serial sidecar can reduce ownership on host paths while retaining direct PHY only where required; abandoning direct PHY would be a product decision. Deciding tests: stock firmware version pins, exact RF/serial vectors, stock-to-owned and owned-to-stock on physical radios, routing/ACK behavior, nonce/source/key binding, airtime/duty constraints, reconnect/readback and firmware memory. Avoid replacing independent protocol code with GPL firmware schemas/libraries without explicitly reconsidering the distribution goal; generic wire-codec libraries do not require that change.

**tinySSB verification. Keep the deliberately narrow leaf.** `crates/tinyssb-core/src/lib.rs:4-11` verifies the pinned 120-byte v0 feed format with caller-owned state, without allocator, transport, clock or persistence. It is not another competing general replication stack. Replacing it with p2panda would break the external wire format; embedding the upstream C++ ESP32 stack would defeat this narrow Rust verifier boundary. Deciding test: exact upstream vectors and tampered frame/chunk/sequence/signature refusals; any expansion into retry, persistence or routing should reopen the build-versus-buy decision.

**Gemot governance and authority folds. Keep semantic ownership.** Constitution fold `moot/constitution/fold.rs:70-150` implements founder/quorum permission, stale revision refusal, deterministic proposal selection and committed rules. Typed authorization bridges Servitor capabilities and delegation; Mooting recognition freezes an electorate at a signed revision. Commons folds classify admitted, pending-authority and revoked contributions independently of physical storage. Generic CRDT/auth libraries do not choose these social and product rules. Cedar/OPA-style engines might evaluate a predicate but do not supply deterministic replicated constitutional history, key rotation, Personae bindings or offline authority evolution. Centralize shared mechanics; preserve explicit, testable governance semantics. Deciding test: permutation convergence, concurrent proposals, quorum duplicate signers, stale/amended rules, revocation/expiry, namespace isolation, cold reopen, authority-dependent projection and authorized retention.

## Limits

This inventory covers the main owned network/protocol mechanisms and their supplier seams. Firmware flashing/USB package admission, product UI, storage engine internals, Fetch/cache/cookie standards and the full identity authority stack are outside this report. External API capabilities were checked against primary project/documentation sources; no candidate dependency was built or benchmarked. Existing tests and retained receipts establish the intended deciding gates, not current pass results.
