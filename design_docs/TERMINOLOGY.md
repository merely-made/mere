# Terminology

Canonical current terminology for the Mere workspace. The [lexicon brief](2026-05-04_lexicon_brief.md) preserves naming history; current definitions live here. Dated draft refinements remain distinct from settled vocabulary and implemented contracts.

For terms not addressed here, see the donor harvest indexes ([full harvest](mere_docs/research/2026-05-27_graphshell_docs_full_harvest.md), [concept brief](mere_docs/research/2026-05-17_graphshell_harvest_brief.md)). The donor `graphshell` repo is GitHub-archived (read-only) and its local clone was deleted 2026-05-27, so the old `../../graphshell/design_docs/` path no longer resolves.

## Top-level

- **Mere** — the platform: an application framework for useful data projections, retained content, peer exchange and governed operations. It preserves identities and their relationships to people, domains and communities. Lowercase **a mere** names one dataspace; **Turnstone** names the browser application.
- **Turnstone** — the browser application. It composes the stack with browser taxonomy, navigation, acquisition, authority and browser chrome. Graphshell and Turnstone remain distinct applications; native Pelt/Genet is their baseline, with external producers optional under the [suite composition ruling](2026-08-22_turnstone_suite_composition_and_capability_census.md). Its graph canvas is a projection of a mere.
- **Genet** — the native render engine: document/UI layout and presentation through the shared wgpu render lane, with static and scripted document capabilities. It supplies the native Pelt baseline; Cambium presents shared application UI through it. External system-webview, Servo and Chromium producers have separate adapters and capability gates. The [suite composition ruling](2026-08-22_turnstone_suite_composition_and_capability_census.md) defines the native baseline; the [embedding draft](2026-08-12_family_composition_thesis_brief.md#embedding-in-caller-owned-wgpu-contexts-draft) proposes caller-owned GPU hosting.
- **Cambium** — the shared UI and scene framework between renderers and applications. Its widget and scene families retain their own state models; Genet hosts the native retained UI lane. Rootstock holds shared host lifecycle/input behavior, with platform event sources supplied by the native and browser hosts. See the [native host](../crates/cambium/cambium-rootstock/src/lib.rs) and [suite composition](2026-08-22_turnstone_suite_composition_and_capability_census.md).
- **Merely** — the organization and brand namespace for Mere and the sibling stack, capabilities and applications.

## Architectural roles (printing-press metaphor)

- **Engines** — at platform scope, the two named roles are **Genet**, the render engine (document/UI presentation), and **Mere**, the projection engine (which data and relationships a view presents, in what context and under whose authority). Specialized formats and domain libraries supply capabilities rather than additional platform-engine roles. Inker retains `Engine` and `SurfaceEngine` as code identifiers for document readers and producer factories; those compatibility names do not redefine the platform vocabulary. The role distinction was ruled 2026-09-05; current composition follows the [suite ruling](2026-08-22_turnstone_suite_composition_and_capability_census.md).
- **Reader** — a concrete content parser implementing `inker::Engine`. Prose says *reader*; the code identifier stays `inker::Engine`, migrating opportunistically like `edge` (see **link**). **Nematic** is the portable smolweb reader family (Gemini/Gopher/Markdown/RSS-Atom and the rest listed under Reader layer).
- **Inker** — reader and surface-producer routing/lifecycle family. It selects a registered content handler for an address: document readers return portable `EngineDocument` values, while surface producers supply long-lived views, frames, input and capability events. Network/disk acquisition remains with the host. The registries retain `EngineRegistry` and `SurfaceEngineRegistry` as code identifiers. Inker also owns the **flip**, transferring the view/session state supported by both content presentations. See [document readers](../crates/inker/inker/src/engine.rs), [surface producers](../crates/inker/inker/src/surface_engine.rs) and [flip](../crates/inker/inker/src/flip/mod.rs).
- **Platen** — graph-aware composition surface. Knows graph semantics; presses node-data into renderable form for the tile layer to receive. Also the projection half of the workbench: `forme` owns what a workbench *is*, platen projects it as a tree.
- **Graphshell** — Mere's reference port and projection host. It provides local retained Mere sessions, graph views, handler routing and cross-application curation, and can consume granted remote projections/intents from source authorities on other devices. Its native retained-content lane composes Pelt with Genet. Mere session/storage owners retain data authority; a remote appearance does not transfer its source's authority to the client. Current application ownership follows the [suite composition ruling](2026-08-22_turnstone_suite_composition_and_capability_census.md).
- **Eidetic** — the memory family backing meres: retained content, source evidence, browsing encounters, stores/journals, session records and codicil archives. **Muniment** owns durable stores and journals; **Pandect** owns retained session records and their curation; a codicil freezes a retained session for later opening or exchange. Ownership was settled by [stack seams S10](mere_docs/implementation_strategy/2026-10-04_stack_seams_plan.md); current intake, clips and preservation work belongs to the [Eidetic development plan](eidetic_docs/implementation_strategy/2026-10-11_eidetic_development_plan.md).
- **pandect** — Eidetic's session layer: "everything a Mere session gathers under one cover", meaning session manifests, graph and view sidecars, journals, worker declarations, content and facet stores, settings, and the persona wallet's carry lane (`crates/system/pandect`). It freezes a live session into an Eidetic codicil and thaws one back (`graph_codicil.rs`). Its stored per-session view record is the **curation** record: the curation plane's hidden relations, folds, and camera, today's `ViewIntent` there, renamed when touched with the stored file name still read (ruling S8). Ruled by Mark 2026-10-04 (rulings S8 and S10 of the [stack seams plan](mere_docs/implementation_strategy/2026-10-04_stack_seams_plan.md)).

## Ports and hosts

The port law ([composition thesis](2026-08-12_family_composition_thesis_brief.md)): the stack owns a capability, a **port** is its first-party embeddable embodiment, and applications compose the relevant subset. Ports live in `mere/ports/`.

- **Castellan** — the identity port: the embodiment of the `personae` capability. Its keeper surface (`view`, `projection`) renders *about* secrets and never contains them; `PersonaeHost` (`authority`) holds the vault, serves the SSH agent, brokers approvals, and applies intents. Founded 2026-08-14 when graphshell's identity surface moved out to it. Castellan owns no repository of its own.
- **pelt** — the tiled reference browser over the render lane, with the static and scripted adapters: `ports/pelt` (`core`, `desktop`). Moved from genet to mere with the other application components; it is a port of the stack, not of Genet. A genet is a clonal colony, an animal's pelt is what it shows the world.
- **ortet** — Genet's raw host: one window, one document, no chrome (`genet/ports/ortet`). The original individual a clonal colony descends from; the one headed port that proves Genet runs with no Mere crate in its dependency cone (`assert_ortet_cone`). Distinct from pelt, which composes Mere.
- **Scrying** — the optional system-webview producer family, adapted by `scrying-engine` as `scrying.web`. It exposes backend-specific frames and capabilities; the host imports supported native frames into its GPU context with the declared format, synchronization and resource lifetime. It is distinct from the native Pelt/Genet baseline, the Graft/Servo producer and the Weld/Chromium producer. Current definitions follow the [adapter](../crates/inker/engines/scrying-engine/src/lib.rs) and [declared capabilities](../crates/inker/engines/scrying-engine/src/translation.rs).
- **Fleece** — the content-gathering family: document extraction, clipping, goal-directed bounded traversal and optional explicitly started acquisition. Genet supplies the lightweight DOM extractor (`fleece-extract` in Mere's workspace); Mere's `mere-fleece` composes gathering and retained-content bridges. Source acquisition, storage, graph admission and operational authority remain with their named owners. Selectors and source/capture evidence accompany extracted material. See the [current capability](../crates/fleece/README.md) and [Eidetic development plan](eidetic_docs/implementation_strategy/2026-10-11_eidetic_development_plan.md).
- **tabard** — the shared theme and design-token library: the derived palette as a DTCG (Design Tokens Format Module 2025.10) token tree, from which the CSS custom-property emitter and the host theme-struct emitter are both derived.

## Substrate (graph truth, persistence, motion)

- **kernel** — the portable identity, authority, and mutation kernel (`crates/graph/graph-kernel`): where graph truth lives. Compiles to `wasm32-unknown-unknown` with no UI, GPU, Servo, or platform I/O dependencies. Everything on a canvas is a projection of kernel state.
- **chartulary** (aka *chart*) — the generic content-addressed container graph: a `Graph<N, E>` where nodes are content-addressed containers and edges are typed relations, over one shared app-agnostic model. A chartulary is the register a house kept its charters and muniments in. Realizes **nested graph** containment; `chartulary::rdf` holds the RDF projection.
- **muniment** — the portable persistence store: the muniment room where a household keeps its deeds as evidence. Durable state and nothing more; the storage under Eidetic, Stickleback, and every journal.
- **Journal** — `muniment::Journal<T>`, an append-only log of immutable entries with `append` and `replay`; edits are never destroyed, a change is a new entry. The plain storage primitive, distinct from a **Codicil** (a typed, content-addressed record) and from **Hagiograph** (a view over journals).
- **seiche** — Rapier-backed force integration: the crate that realizes the graph's bodies as motion (`crates/conatus/seiche`). A seiche is the standing-wave oscillation of a lake, the whole body of water rocking; it moves the *mere* the way this crate moves the graph's bodies. Owns colliders and therefore press/select/drag (see **gnode**); holds tensor force laws.
- **sceno / scenomise / scenotime** — the scene family under Cambium: **sceno** defines scene snapshots, source/occurrence references, footprints, spaces and measurements; **scenomise** owns the arrangement/solver registry; **scenotime** owns the temporal part. **Scenograph** is the host-neutral scene-authoring model at `crates/cambium/scenes/scenograph`. A **scene** is a projection's placed result and has an authored recipe; a physics simulation is a **world**; renderer operations are the **paint list**. Names and boundaries: [stack seams S1/S6](mere_docs/implementation_strategy/2026-10-04_stack_seams_plan.md); authoring work: [Scenograph editor plan](mere_docs/implementation_strategy/2026-10-07_scenograph_editor_plan.md).
- **arrangement** — positions: where a scene's items are placed, by one of sceno's analytic families (spiral, grid, geographic, timeline, kanban and the rest) or a registered custom one; physics acts on an arrangement and is not one (dynamics plan F11). Not the workbench's tile structure, which is a **forme**. Ruled by Mark 2026-10-04 (ruling S5 of the [stack seams plan](mere_docs/implementation_strategy/2026-10-04_stack_seams_plan.md)); `forme::Arrangement` and the kernel's Arrangement relation family keep their identifiers until touched, under the `edge` rule, with the persisted tag still read.
- **forme** *(count noun)* — a workbench arrangement: the geometry-free structure of frames, tiles and splits that a workbench locks up for platen to press, as a printer's forme locks type for the press. The crate `forme` owns it (see **Platen**). Ruled by Mark 2026-10-04 (ruling S5 of the [stack seams plan](mere_docs/implementation_strategy/2026-10-04_stack_seams_plan.md)).
- **world** — a physics world: the bodies, joints, fields and emitters a simulation steps, as seiche's `SceneSpec` describes and conatus's `BodyWorld` holds. Not a **scene**, which is a projection's placed result. Ruled by Mark 2026-10-04 (ruling S6 of the [stack seams plan](mere_docs/implementation_strategy/2026-10-04_stack_seams_plan.md)); `SceneSpec` and the physics scenes plan's wording migrate when touched.

## Surfaces (frame tree)

Terms from the [graph roster and frame taxonomy](mere_docs/design/2026-06-07_graph_roster_and_frame_taxonomy.md).

- **frame** — a leaf of the window's frame tree. Panes and the workbench are frames.
- **pane** — a frame-tree leaf answering one question about the graph or system: roster ("what is in the graph"), gloss ("how do I see and navigate it"), inspector ("what is this page made of"), apparatus ("how is the system doing"), comms. Summoned, toggled, and arranged from the shellbar.
- **tile** — a slot of node content inside the **workbench** (the tile tree: tabs and slots of pages). A tile shows what a node references; a pane shows something *about* the graph. Tiles can be torn out to other windows over the same backing graph.
- **shellbar** — the docked, edge-configurable chrome strip outside the frame tree that summons, toggles, and arranges panes: the frame tree's own UI. Its screen edge (Left/Right/Top/Bottom) is the *edge* sense unrelated to graph edges.
- **Navigator** — the historical name for the single graph-navigation surface per window, configurable in scope and form factor and never split into instances. Ruled 2026-06-07: *the Navigator is gloss, expanded*. Use **gloss** for the pane; *Navigator* survives only in older docs and in the phrase "expanded radially in the Navigator" under **volvelle**.

- **surface producer** — a long-lived content presentation driven by an Inker host: commands and input enter it; frames, semantic updates and typed outcomes leave it. Code retains `SurfaceEngine` for the factory and `SurfaceProducer` for each instance. Native-frame format, synchronization and allocation epoch are part of the contract. **Scrying**, **Graft** (Servo) and **Weld** (Chromium/CEF) are the external browser trio; the current native Pelt session/view is a separate baseline. See [surface contracts](../crates/inker/inker/src/surface_engine.rs).
- **embedding** — placing a capability, view or application component inside a containing host through declared interfaces. The [caller-owned wgpu draft](2026-08-12_family_composition_thesis_brief.md#embedding-in-caller-owned-wgpu-contexts-draft) proposes host-supplied Device/Queue and frame targets, with adapters for scheduling, input, focus, IME, clipboard, accessibility and lifecycle. Data/session authority remains independent of the rendering host. General egui/Iced or other toolkit adapters are qualification targets.
- **paint leaf** — a retained custom-paint element, such as a graph canvas, waveform or knob, whose output is common paint commands or a Vello scene. Sprigging owns the [leaf interface](../crates/cambium/sprigging/src/lib.rs). This describes rendering composition rather than the identity or sharing boundary of a resource.
- **resource leaf** — **draft reading (2026-10-13)** of a resource as a meaningful unit of identity and sharing at a chosen granularity. A document may be a leaf in one view and a composition of independently addressed parts in another. Separate accesses/appearances keep their own identities; explicit subclips have identity and lineage, while a selector alone does not create an entity. See the [resource leaves draft](2026-08-12_family_composition_thesis_brief.md#resource-leaves-and-sharing).

## Reader layer (inker / nematic / document model)

- **Reader** (code: `inker::Engine`) — a parser returning an `EngineDocument` from already acquired content. The concrete catalog lives in [Nematic's registry](../crates/nematic/nematic/src/lib.rs): Markdown, Gemini/gemtext, Gopher, feeds, text, files, Finger, Knot and its Djot body, Scroll, Misfin, Nex, Guppy, Spartan, Titan, Micron and its compatibility subset, plus feature-gated HTML fragments. An HTML-fragment reader lowers supplied fragment content; it is not the native document runtime or an external browser producer. Reader IDs and the `genet.web`, `host.external-protocol` / `graphshell.internal` routing identifiers retain their code meanings. Registration and host feature selection decide availability; a listed identifier is not proof that every application loads that handler.
- **Protocol-faithfulness rule** — protocol readers (gemini, gopher, RSS/Atom, finger, scroll, misfin, nex, guppy) populate document blocks only with what the source spec actually says. They do not invent semantic structure the spec doesn't define. RSS `<item>` becomes `FeedEntry`; finger plain text stays plain text; gopher menu items use the `gopher://` URL synthesis from RFC 4266. The only Mere-defined format that's allowed to be richer is **knot**.
- **Semantic-block intent** — the four `Block` variants beyond structural shape that name *what content means*, not just *how it's laid out*: `FeedHeader`, `FeedEntry`, `MetadataRow`, `Badge`. Intelligence layers (search, summarise, recommend, recall) match on these intents. Adopting them in protocol readers is *more* spec-faithful (RSS / Atom literally have entry-typed items), not an invention.
- **Trust ladder** — the `DocumentTrustState` enum: **Trusted** (verified through a chain of trust — TLS root, signed envelope), **Tofu** (first-contact-accepted, "trust on first use"), **Insecure** (unauthenticated transport — plain HTTP, file://), **Broken** (verification attempted and failed — cert mismatch, sig invalid), **Unknown** (default; not yet evaluated).
- **Provenance** — `DocumentProvenance` carries `source_kind` (engine ID), `canonical_uri`, `fetched_at` (RFC 3339), `source_label`. Readers populate `source_kind` + `canonical_uri`; the host fills in `fetched_at` after transport.
- **Knot** — Mere's native note / clip format. Frontmatter (YAML subset) + polyglot CommonMark body where fenced code blocks with protocol language tags (`gemtext`, `gopher`, `nex`, `feed-entry`, `feed-header`, `metadata-row`, `badge`) expand into real semantic blocks. Wikilinks `[[name]]` rewrite to `mere://node/<slug>`; hashtags `#tag` extract to `Badge` siblings. The only Mere-defined content format. Engine ID `nematic.knot`; default content-type `text/x-knot`.

## Comms layers

**Product ruling, 2026-09-13:** **Gemot** is the community surface containing
**murmurs** (secret conversations), **moots** (spaces of agreement), and **coop**
(shared activities among peers). Use these names; explain the activities in
plain language within them. Write `coop` without a hyphen. The technical
`gemot` library owns governance; the presentation currently lives at
`ports/moot` (`mere-moot`, library `moot`). Package coordinates do not redefine
the product. The active execution plan is the
[Gemot continuation](2026-08-22_turnstone_suite_composition_and_capability_census.md#gemot-murmurs-moots-and-coop-2026-09-13).

- **Stickleback** — the shared replicated-space layer beneath every signed peer
  domain: joined spaces and their drain, policy-before-insert processing,
  muniment-backed replicated storage, checkpoints, retention mechanics, and
  native drop carriage. The package is `stickleback`. It was `murm-replication`
  until 2026-07-26, when the multi-consumer reality (Murm, Mesh, Moot, and
  transport) earned it a name for the boundary rather than one consumer. A
  domain supplies its own operation grammar, addressing, authorization, and
  materialization — Stickleback never infers authority from transport access or
  visible membership.
- **Murm** — the peer-exchange family, a domain over Stickleback. Its public
  conversation service owns invitation-scoped conversation history and exchange.
  Coop uses shared admission and exchange machinery, while each application
  owns its collaborative state and operation semantics.
  - **Murmuring** — retired inner crate. Its signed-operation grammar and
    conversation engine were folded into `murm` on 2026-07-14. Internal
    mechanics use `ConversationEngine` and `ConversationStore`.
- **Moot** — the governed-space domain over Stickleback. It owns community
  identity, membership, constitution, governed settings, moderation,
  recognition, Standing, Tulpa adoption, FLORA receipts, and community
  projections.
  - **Mooting** — current home of recognition policy and, temporarily, the
    generic `MunimentStore`. The store moves to `stickleback`; the name is
    not a generic-plumbing law.
- **Moothold** — reserved for actual multi-moot holding or federation behavior.
  The current package also contains single-moot code for historical reasons;
  that code becomes the public Moot service during the peer-runtime reframe.
- **Gerund law (retired 2026-07-12)** — `murmuring`:`murm` ::
  `mooting`:`moothold` described the old workspace partition, not a durable
  semantic rule. The `murmuring` package was folded into `murm` on 2026-07-14.
  Use role-descriptive internal names and keep the product words for product
  concepts.
- **Gazetteer** — handle-resolution index: turns a name / handle / key into reachable, trust-stated endpoints (WebFinger today; NIP-05 / atproto-did / moot web-of-trust to come). An index / *directory*, not a broadcast *gazette*, so it sits on the persona / identity tier (`ports/gazette`; the crate is `gaz`), promoted out of the murm supercrate 2026-07-08. Incubating — no consumer wired yet, and its blocking HTTP needs an async port first.

## In-product vocabulary

- **clip** — a portable content unit made by meaningful selection, capture or
  export: a passage, document, screenshot, recording or supported structured
  data, for example. It may have several payloads and internal semantic
  structure. Its boundary is what can usefully be taken and shared, rather
  than a required smallest atom. A clip's source, captured version and projected
  appearance are distinct. Accepted direction and proposed lifecycle policies:
  [family composition brief §8](2026-08-12_family_composition_thesis_brief.md#8-primary-data-model-clips-and-live-entities-2026-10-11).
- **live entity** — an entity with domain identity and operations independently
  of any capture, such as an authored object, field, device, active session or
  shared activity. A disclosed projection, captured clip and permission to act
  on its source are different things. Its domain retains operational authority.
  This is a model term, not a new universal runtime type. See the
  [family composition brief §8](2026-08-12_family_composition_thesis_brief.md#8-primary-data-model-clips-and-live-entities-2026-10-11).
- **murmur** — a secret, invitation-scoped conversation
  between identified participants. A murmur is the container, and individual
  posts are utterances within it. Participant count does not select Murm versus
  Moot; a Moot is distinguished by durable governance. Product surfaces say
  murmur. Privacy is a capability to prove for the selected path: a public mesh
  channel or possession of a shared radio key does not establish secret,
  individually authenticated conversation. Foreign protocol views retain their
  actual privacy and delivery facts.
- **coop** — peer-to-peer shared activity, such as editing or browsing together.
  It can happen within a moot or through a temporary invitation. The application
  owns what changes; governance applies when the activity belongs to a moot.
- **Cable** — the semantic ancestry for conversations, channels, and signed
  posts. `mere/cable/v1` names Mere's Cable-shaped p2panda dialect. It does not
  claim wire interoperability with the cabal-club Cable protocol. Use
  `Conversation*` (`ConversationId`, `ConversationKey`, `ConversationHandle`)
  for storage/runtime mechanics and keep Cable terminology at this explicit
  protocol boundary. The borrowed *cabal* type prefix is retired (2026-09-05):
  it named cabal-club's thing while disclaiming cabal-club's wire format.
- **moot** *(count noun)* — a persistent themed federatable graph-view community: what a mere becomes when shared. Ruled with Mark 2026-07-30, two faces: the genesis face (a moot *begins* when your mere is shared; the tiers are escalating socialization of the mere, the datastructure moot makes social) and the grown face (a mature moot may govern one or more meres, which is the region-grafting model; a shared world never stops being a mere). Substrate rule: solo meres are born share-ready (one-writer signed spaces), so becoming a moot is a membership change, never a format migration
- **fili** — reserved name for Moot lineage: community ancestry, forks, and
  genealogy across related moots. Do not use it for ordinary event history,
  retention, or storage mechanics.
- **Hagiograph** — the legend and memorial layer: what memory makes of history
  through legends, memorials, epithets, and retelling. It is a view over event
  journals, distinct from the journal itself, an immutable Eidetic Codicil,
  and Moot descent in **fili**. This is the meaning formerly assigned to the
  standalone `tulpa` reservation; renamed 2026-08-31.
- **Tulpa** — a Moot's community-recognized, revisioned shared artifact and
  persistent collective identity. Signed proposals freeze their recognition
  electorate; endorsements adopt an exact artifact version; revocation and
  rollback change the effective projection while retaining every source fact.
  Tulpa takes the collective role formerly discussed as *egregore* and lives
  inside `gemot`, not as a standalone crate. A FLORA candidate may become a
  Tulpa through this adoption lane, but Tulpa is not limited to model weights.
- **gemot** *(count noun)* — a sovereign assembly of mootholds (t4; renamed from *coalition* 2026-07-30, which had renamed *demesne* 2026-06-04). OE *gemōt*, the collective form of *mōt* itself: the assembly of assemblies, rejoining the moot/moothold word-family where *coalition* was the Latinate outlier. crates.io `gemot` already held (0.1.0, claimed 2026-07-14 as the assembly-layer crate: Moot lifecycle, governance, replication, Standing, Tulpa, and FLORA), so the t4 count noun and the governance crate share the name deliberately
- **suzerainty** *(relation)* — the outer-tier ↔ inner-member relationship (moothold ↔ moot, gemot ↔ moothold); overlordship without absorbing internal sovereignty
- **volvelle** — UI form factor: a moot expanded radially in the Navigator (medieval rotating-disc knowledge instrument)
- **astroid** — internal UX vocab for hub-collapse: collapsing a subgraph to its central node forms an astroid-shaped boundary curve. The result is a *supernode* (derived, rebuilt per view, never synced), not a nested graph
- **servitor** — the resident helper unit: an installed extension or local agent, living as a node bearing a nested graph, holding a personae identity and a capability grant, proposing changes through the participant gate (so it cannot exceed its grant, and every act is attributed and revertible). Chosen by Mark 2026-07-17 for the chaos-magic sense: created, named, task-scoped, dissolvable. Crate name reserved on crates.io the same day (0.0.1). A human peer is never a servitor; both are *participants*. *Animula* (Hadrian's "guest and companion of the body") is banked as the companion-flavored runner-up. See the [participant gate and packs plan](archive_docs/2026-10-06_completed_plans/2026-07-17_participant_gate_packs_plan.md)
- **participant** — anything admitted to act through the gate: a personae identity holding a grant and the right to submit petitions. Human moot peers, servitors, and scenario runners are participants; the trusted UI uses the direct attributed commit path. Restored by Mark 2026-09-20, superseding the 2026-07-17 use of *denizen* for this role. Existing `Denizen*` APIs, `mere.denizen` delegation domain, `denizen.binding` facets, author prefixes, action IDs, and saved paths retain their compatibility spellings; they describe participants and do not give the simulation term authority over the platform.
- **denizen** — reassigned by Mark 2026-09-20 to Isometry's simulation family: an inhabitant remembered individually because of its history, relationships, or explicit designation. The canonical definition and tier consequences live in `isometry/mesocosm/design_docs/2026-09-18_wing_design_plan.md`, §3.2.1. The term and prospective crate name belong to that simulation concept; this ruling creates no crate, transfers no Servitor implementation, and makes no crates.io availability claim.
- **petition** — a participant's proposed change: a typed batch (graph edits lowering to captured deltas, app effects as Actions) validated against the grant and the journal revision before atomic, attributed apply. The journal records granted petitions. Ruled 2026-07-17 (replaces the working word *proposal*)
- **watch** — a participant's subscription: the scope of the graph whose committed changes wake its body, with the containment law watch ⊆ read ⊆ grant (you cannot be woken by what you cannot read). Watches are declared in the pack manifest and reviewed at install beside the rings; a chain of wakes is a *cascade*, bounded by a budget that is a setting. Ruled by Mark 2026-08-13. Code note: `Watch` will collide with `tokio::sync::watch` and filesystem watchers; prefer `GraphWatch` or similar at the type level. See the [graph behaviors plan](mere_docs/implementation_strategy/2026-08-13_graph_behaviors_plan.md)
- **pack / mod** — the installable-bundle words, split by trust depth (ruled 2026-07-17): a **pack** is the plain user-facing word for a shallow-rung bundle (scenario/macro data, scripts; "campaign pack", "command pack"), a **mod** is a deeper-rung bundle (wasm components and beyond) whose grant reaches further. One Eidetic Codicil envelope sits underneath. Coheres with the existing `register-mod-loader` / `WasmModRuntime` naming
- **swatch** — a mere seen at a scope, small enough to embed: a scope (a node, a subgraph, a nested graph, or a whole mere) and a mode. A *projection* swatch owns a recipe (an authored projection definition and its variant), which compiles to a scene; a *reflection* swatch follows another view's recipe and camera live (a minimap is one). A portable fact, not a widget: a gloss pane shows one, a facet composes several into a grid whose cells may differ by scope, arrangement or dynamics, with shared or independent scales declared per axis, and an embed carries one onto another surface or site. Cambium's graph canvas and pictograph are ways to draw it. A representation, never an identity: the graph lives in the kernel and its curation in pandect. A swatch over a servitor's nested graph is that servitor's inspection UI. Restated 2026-10-08 ([Scenograph editor plan](mere_docs/implementation_strategy/2026-10-07_scenograph_editor_plan.md), SE53 to SE61); first worded 2026-07-17.
- **gloss** — the graph-navigation pane: one surface per window, configurable in scope and form factor, that displays a swatch so the user can see their data differently without altering the main graph. It is what the *Navigator* became (ruled 2026-06-07); an outline is form-factor-agnostic and scope is the dial. This is the only sense of *gloss* in project docs; for the explanatory sense say *shorthand* or *informal name* (ruled 2026-09-05)
- **nested graph** — a graph (a set of relations) contained *within* a node: authored, and it syncs. Contrast: a **subgraph** is a selection of kernel nodes and the links among them (a scope, never a container, never synced as a thing); a **supernode** is a subgraph collapsed for display (derived, see *astroid*); a *swatch* is a representation that may show a nested graph but never is one. *Graphlet* is retired (2026-09-05) and left to network science, where it means a small induced-subgraph motif. Ruled 2026-07-17; realized by the chartulary containment capability per the [participant gate and packs plan](archive_docs/2026-10-06_completed_plans/2026-07-17_participant_gate_packs_plan.md)
- **resource** — the addressed thing apart from any particular access or appearance. In the graph kernel, Resource identity is keyed by canonical IRI; browser addresses use a UUIDv5 of that canonical IRI. Content assertions and tag concepts belong to the Resource stratum. Several independent **surfaces** can show one Resource, and navigation changes a Surface's shown binding while the Resource retains its claims. Resources may be undrawn; projection can lift their links onto visible surfaces. Code uses `ResourceNode` and `SurfaceNode`; generic *node* covers either stratum. Identity and ownership follow the [graph semantics rulings](mere_docs/implementation_strategy/2026-10-04_graph_semantics_plan.md). Native domain identities retain their declared contracts under the [primary data model](2026-08-12_family_composition_thesis_brief.md#clips-live-entities-and-appearances); the resource-leaf draft does not impose one identity scheme or smallest unit on every domain.
- **strata** *(sing. stratum)* — semantic divisions of a mere's graph. The implemented pair is the **resource stratum** (things and claims about them) under the **surface stratum** (particular encounters: navigation, trail, layout, groupings and collections). A surface rests on the resource it shows; the resource stratum stands alone. Nodes have identities in their respective strata; a statement's declared nature selects its owning stratum when recorded, and existing assertions retain their recorded ownership. Ruled by Mark 2026-10-04 and amended 2026-10-05 ([graph semantics plan](mere_docs/implementation_strategy/2026-10-04_graph_semantics_plan.md), rulings 6, 10, 13, 14, 19 and 26). Strata are one **aspect**, distinct from node types, selections (*subgraphs*), containment (*nested graphs*), attention and the truth / ambiance / curation *planes*: both implemented strata are truth. **Draft extension (2026-10-13):** additional strata would need distinct identity, owned facts, lifecycle and inter-stratum contracts; the current Resource/Surface enum does not support user-defined strata. Tagging, indexing and query views can organize existing strata. See the [strata and query views draft](mere_docs/implementation_strategy/2026-10-04_graph_semantics_plan.md#7-strata-and-query-driven-views-draft).
- **surface** — what the user browses in: an element of the surface stratum that shows one **resource** at a time and carries the trail, layout, groupings and collections. Navigating in place changes which resource it shows. Code says `SurfaceNode`, with `Node` and `NodeKey` kept as compatibility names; `SurfaceId`, which names chrome and accessibility elements, is a different thing. The 52 existing `*Surface*` types use the word in the UI-composition sense, which this graph sense does not replace. Ruled by Mark 2026-10-05 (ruling 19 of the [graph semantics plan](mere_docs/implementation_strategy/2026-10-04_graph_semantics_plan.md), amending ruling 12).
- **tag** — a resource representing a vocabulary concept, with its own IRI, label and possible broader/narrower concepts. Tagging is an attributed statement connecting a thing's resource to the concept. Vocabulary identity belongs to a stable owner; equal labels from different owners do not identify the same concept, and another owner's concept can be reused explicitly by IRI. Ruled by Mark ([graph semantics plan](mere_docs/implementation_strategy/2026-10-04_graph_semantics_plan.md), rulings 15 and 20). A vocabulary graph or tagging view can present these resources separately while they retain Resource identity; it does not establish a tagging stratum.
- **saved query** — an addressable selector spec for a linked subgraph, evaluated over the available graph with a coverage note. Sharing sends the spec for evaluation over the receiver's own data. Freezing records Resource members, the spec and its source revision in a nested graph. Ruled by Mark ([graph semantics plan](mere_docs/implementation_strategy/2026-10-04_graph_semantics_plan.md), ruling 3 and P4). The current SPARQL membership adapter accepts SELECT with a named member column of Resource IRIs. A query-driven view adds an appearance/arrangement policy; membership does not identify one particular surface or open one implicitly.
- **SPARQL** — the query language for RDF graph patterns ([W3C specification](https://www.w3.org/TR/sparql11-query/)). Mere evaluates it over the kernel's RDF projection and reports coverage; the current row adapter supports SELECT and ASK, while saved membership requires SELECT. CONSTRUCT/DESCRIBE graph results are not supported in the current adapter. SPARQL defines a query; RDF named graphs scope statements; neither defines a Mere stratum. See the [query views draft](mere_docs/implementation_strategy/2026-10-04_graph_semantics_plan.md#7-strata-and-query-driven-views-draft).
- **index** — a lookup structure derived from source records to make retrieval efficient. In the [query views draft](mere_docs/implementation_strategy/2026-10-04_graph_semantics_plan.md#7-strata-and-query-driven-views-draft), an index is rebuildable; its configuration or an authored catalog can have a Resource identity while generated lookup entries remain derived. It does not establish an indexing stratum or replace the source graph's authority. Results still carry their source revision and coverage.
- **aspect** — a way of dividing what a mere holds. Each aspect keeps its own words for its parts, because the words carry its shape: strata stack, planes sit side by side, levels are climbed, tiers escalate. A new way of dividing the graph enters as an aspect, here, and says how it differs from the others. Ruled by Mark 2026-10-04 (ruling 16 of the [graph semantics plan](mere_docs/implementation_strategy/2026-10-04_graph_semantics_plan.md)). Not an aspect: a predicate's properties (nature, behavior, durability, projectability, per the statement kernel brief), though nature decides a statement's stratum.

  | Aspect | Parts | Shape | Source |
  |---|---|---|---|
  | strata | resource stratum, surface stratum | stacked: a surface rests on a resource | graph semantics plan, rulings 6, 13 and 19 |
  | planes | truth, curation; ambiance a third (unruled analysis) | side by side: what is, what a view chooses | swatch primitive design (model); ambiance design §6; curation's stored record is pandect's (stack seams S8) |
  | keeping | ambient level, short-term, long-term, codicil | climbed by promotion | ambiance, ruled 2026-09-23; wording ruling 17 |
  | attention | background, foreground, focus | per view, never synced | ambiance, ruled 2026-09-23 |
  | tiers | t1 mere, t2 moot, t3 moothold, t4 gemot | escalating socialization | **mere**, **moot** entries |
  | coverage | possession, residency, disclosure, synchronization, projection | nested, each narrower | family composition thesis; graph semantics ruling 4 (residency a reading) |
- **mere** *(lowercase, count noun)* — a configurable spatial dataspace holding one data domain: the domain's repository, which several applications can use. An identity's applications can open its meres by default; exceptions require a reason. A mere lives as retained sessions backed by Eidetic and can be opened or exchanged through codicils. Source/session authority governs remote access and permitted copying. An identity's whole governed set of meres is its **reservoir**. Capital **Mere** names the platform. Its dataspace role integrates heterogeneous sources through meaningful relationships; its storage retains native material interpreted through declared formats and adapters. The data-domain boundary was ruled 2026-09-23; the [primary data model](2026-08-12_family_composition_thesis_brief.md#8-primary-data-model-clips-and-live-entities-2026-10-11) distinguishes content, live entities and appearances.
- **orrery** *(form factor)* — the cosmos-style spatial form factor: a whole dataspace seen at once, force-directed and in-scene. A way a **mere** is *rendered*, exactly as **volvelle** names the radial-moot form factor. Narrowed 2026-07-26 from its former lexicon sense ("a user's root graph view", tier 1), which **mere** now carries. Not a tier and not a container; `Scope::Orrery` and "orrery root" in code already mean this form factor, but the enum name says *scope*; rename to a form-factor enum when that file is next touched
- **ambiance** — ambient data: what an engine generates about the rest of a domain, around whatever a person has in focus, while it stays out of focus. Mark, 2026-09-23: "Ambiance can be a term that defines data in the background, ambient data". Isocosm ruling 70, 2026-09-20: "the background of information generated by an engine and localized to a particular address/place/scene". Mark's example is Wikipedia's unclicked links. Two independent axes place anything a person meets. **Attention** runs background → foreground → focus; it is view curation, per instance, and never synced. **Keeping** runs ambient → short-term → long-term → codicil. *Ambient* material is generated, regenerated on demand, never stored and never in conflict. Above it are Alembic's three levels of memory: short-term (*Recent*), which is evicted by default and is where examined material lands; long-term (*Saved*), reached by an affirmative promotion such as tagging or bookmarking; and **Codicil**, which is immutable, content-addressed and shareable. **The ambient tier** is keeping's bottom level, where ambiance sits. A move between keeping levels may be explicit, permissioned, scripted or automatic. Each move is recorded in the structural event log with who or what made it: the person, or the rule, script or engine with its version. The ambient tier is not one of the t1–t4 socialization tiers, and ambiance is not the physics ambient pulse or living backdrop, which paint system state behind the graph. *Keeping* is not **Standing**. Ruled with Mark 2026-09-23; design record: [ambiance design](mere_docs/design/2026-09-23_ambiance_design.md). **Amended 2026-10-04 (Mark, [graph semantics plan](mere_docs/implementation_strategy/2026-10-04_graph_semantics_plan.md) ruling 17):** say **the ambient level**, since keeping's steps are all levels; *tier* keeps the socialization sense. Meaning unchanged; text written before the amendment keeps "ambient tier".
- **reservoir** — an identity's whole governed set of meres, one mere per data domain. Minted 2026-09-23 (Mark) at the scale of IBM's coinage: "The data reservoir is a reference architecture that balances the desire for easy access to data with information governance and security", for a whole organization ([IBM Redbook SG24-8274](https://www.redbooks.ibm.com/abstracts/sg248274.html)). Before that date the word appeared here only as shorthand for a mere read as a governed lake. A data domain is not a reservoir; it is one mere within one. The word is unrelated to *reservoir sampling*, the random-sampling algorithm
- **Standing** — community-scoped reputation derived from signed receipts of
  commitment follow-through. It accrues against a persona-chain root and is a
  deterministic projection, not a transferable token. The previous name was
  **Tessera**. Existing `tessera.redb` stores and serialized
  `tessera_operations` remain readable during migration.
- **Codicil** — Eidetic's canonical schema-typed, immutable,
  content-addressed exchange record. This replaces **Engram**. The old source
  alias and legacy schema tags remain readable; new schemas and APIs use
  Codicil. An append-only sequence of events is instead a
  `muniment::Journal<T>`.
- **FLORA** — federated LoRA. In the Wang et al. FLoRA protocol, participant A
  factors stack vertically and B factors horizontally, with each participant's
  scale applied once to B. Heterogeneous ranks sum to the exact global rank
  under an explicit budget. Lower-case *flora* meaning a Moot's accumulated
  payload collection is retired; that was a capitalization-driven
  misunderstanding.
- **kith / kin** — contact tier distinction: *kith* = those known to you; *kin* = close. Orthogonal to moot membership.
- **gnode** — a node's rendered body on a graph canvas: the visible, spatially-placed object standing at the node's position in an orrery or swatch. A projection, never truth: rebuilt per frame from kernel truth plus seiche's live state, stores nothing. At most one per (node, pane instance); zero when off-scope/off-pane (the node demotes to an underlay dot, which is not a gnode). Anatomy: **body** (silhouette or custom hull, spatially coincident with the seiche collider: the face IS the collider), **face** (the body's texture: state color, favicon, or sprite), **caption** (label beside, LOD-driven); emphasis channels: selection = ring + lift, hover = wash, focus = focus ring, with color reserved for activation state. One primitive, two render tiers: a chrome-DOM `.gnode` element (focused pane) or an in-scene Scene layer (secondary panes; `render_gnodes_as_dom` picks per pane). Pointer-inert: seiche owns press/select/drag through the collider; a11y bounds are read off the gnode's painted rect. Distinct from the **node** (the graph object that references addressed things), from a **card** (summoned *about* a node or selection), and from non-spatial representations (roster row, tile tab, session chip). Etymology: g(raph)-node, coined 2026-06-02 as the orrery pool's CSS class; kept 2026-07-02 for the gnostic reading (the knowable body of the node). Full model: [node_card_summoning_design](mere_docs/design/2026-07-01_node_card_summoning_design.md).
- **relation** — the general word for a relationship. Where graph connections and page hyperlinks appear together, existing product terminology uses *relation* for the graph connection and *hyperlink* for the one in the content. **Refinement adopted (2026-10-13):** relation is the umbrella for a **link** within one semantic stratum and an **edge** across strata. Explicit, computed and inferred describe provenance independently. The runtime `RelationKey` currently identifies stored Surface or Resource edges; the draft umbrella also covers the special shown binding and is not a claim that this handle represents every relation. See the [graph vocabulary draft](mere_docs/implementation_strategy/2026-10-04_graph_semantics_plan.md#7-strata-and-query-driven-views-draft).
- **link** — the user-facing word for a graph connection, adopted 2026-07-04 (Mark: "if I started over today, I'd just call 'em links"). A drawn connection can gather exact assertions, each retaining its own identity, predicate, scope and provenance; each asserter's assertion is retracted separately. Content assertions belong to resources, while surfaces retain their own navigation and arrangement relationships ([graph semantics plan](mere_docs/implementation_strategy/2026-10-04_graph_semantics_plan.md), rulings 1, 2 and 19; [petgraph-RDF plan](archive_docs/2026-10-06_completed_plans/2026-06-18_petgraph_rdf_plan.md)). The existing product-copy rule uses *link* and keeps internal `edge` identifiers, petgraph vocabulary and CSS classes; identifier migration is opportunistic, never a churn pass. **Refinement adopted (2026-10-13):** link specifically connects peers within a semantic stratum. A document-to-tag relationship is a Resource link, and a grouping between accesses is a Surface link. Media type, RDF type and attention do not determine this category. A Resource link drawn between surfaces keeps its Resource origin. See the [graph vocabulary draft](mere_docs/implementation_strategy/2026-10-04_graph_semantics_plan.md#7-strata-and-query-driven-views-draft).
- **edge** — the generic graph-theory and internal storage term, including `EdgeKey`, `ResourceEdgeKey` and `.roster-edge`; these identifiers keep their current meanings. The existing product-copy rule uses *link*. **Refinement adopted (2026-10-13):** edge has a distinct design-language sense for a relation across semantic strata, such as a Surface showing a Resource. The current runtime represents this association as a **shown binding**, costing zero hops in mixed walks; it is not an ordinary stored statement edge. The query-view legend and source inspector adopt this narrower product meaning with distinct configurable stroke cues. Ownership, persisted identifiers and traversal behavior stay unchanged. The shellbar's physical screen edge is an unrelated sense. See the [graph vocabulary draft](mere_docs/implementation_strategy/2026-10-04_graph_semantics_plan.md#7-strata-and-query-driven-views-draft).
