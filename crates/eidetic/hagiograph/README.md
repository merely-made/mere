# hagiograph

The history organ: which events were significant, and the past they are
judged against.

A world's journal records everything that happened. A hagiograph answers
the questions a journal cannot answer by itself:

- **What stands on the record.** High-water marks along axes a product
  defines, with who holds them. Records merge by taking the higher mark, so
  forked and grafted worlds join without a protocol.
- **What was significant.** A feat beats a mark that stood before the
  reckoning. Being first on an empty record is not a feat.
- **Where the past came from.** A generated world should not begin with an
  empty record. Deep time runs the product's own simulation for a set span
  before anyone steps in, so the history a player has to overcome is made the
  same way a played one is.
- **What memory keeps** (later): legends, memorials, epithets and retelling,
  whose presence scales with attention. A legend nobody tells fades.

The boundaries are the point:

- **Not the storage of event history.** That is a `muniment::Journal` or a
  product's own log. A hagiograph judges and generates history; it does not
  store the events themselves.
- **Not a simulation.** Deep time drives the product's simulation through a
  seam. It never simulates anything itself.
- **Not an immutable exchange record.** That is an `eidetic::Codicil`.
- **Not descent.** That is [`fili`](https://crates.io/crates/fili), which
  records continuity of line across worlds.
