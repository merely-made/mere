## Result

Graphshell's current tree Inspector has a **Role groups** selector and an
explicit **Apply role groups** action. It chooses the partition used by group
role overrides. The existing **Groups** selector continues to choose Group
pull's input independently.

The default-role action and the new role-source action use one shared edit path
in `physics_controls`. It reads the canonical DynamicsSpec, changes only the
intended target field, and submits the edited spec to `Canvas::set_dynamics_spec`.
Canvas remains the admission/binding owner. The existing target resolver is
visible only within the Canvas module; no new persisted role field, schema or
supplier pin was introduced.

This retains exact authored Mix shares, seed, bars, realization, channels, other
target fields, and item/group override maps. It avoids reconstructing the root
from runtime f32 values during a role edit. A missing target is materialized from
the current resolved target only when the edit changes it. Same-value actions
preserve an absent target and an explicitly authored empty Site group target.
Unmatched group labels remain stored and fall through to the default role;
switching to a different partition does not make those labels invalid.

The picker reads back the current role-group source on initialization and scene
reopen. Refused actions report their error without marking a successful edit.
